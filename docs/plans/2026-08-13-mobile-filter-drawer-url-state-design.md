# 手机筛选抽屉与网址状态设计

## 问题与目标

歌曲页和视频页在桌面端都有完整筛选侧栏，但 900px 以下直接隐藏侧栏，手机用户只能搜索，无法按团队、类型、版本、Staff 或频道缩小结果。与此同时，搜索、筛选和排序只存在于页面内存中，刷新或分享网址后都会丢失。

本阶段让两页在手机端拥有完整、可访问的筛选入口，并把所有会改变结果顺序或范围的条件保存到网址。桌面端布局、数据格式和现有行展开行为保持不变。

## 交互方案比较

1. **右侧筛选抽屉（采用）**：复用现有侧栏内容，在窄屏把它变为覆盖式抽屉。用户可连续勾选，结果即时更新，底部按钮显示当前结果数。改动集中且桌面零迁移。
2. **底部弹层**：更符合单手操作，但现有筛选项较多，长列表在半高弹层中容易形成嵌套滚动。
3. **独立筛选页面**：信息空间最大，但筛选、返回和结果浏览被拆成多次导航，不适合频繁试选。

视觉继续使用现有浅色资料库操作台语言：白色纸面、冷灰分隔和蓝色强调。抽屉通过细边框、克制阴影和清晰的顶部/底部操作区形成层次，不另造一套组件风格。

## 结构与可访问性

两页加入相同的手机筛选按钮、背景遮罩、抽屉标题、关闭按钮和“查看结果”按钮。共用的 `viewer_controls.css` 负责响应式壳层，共用的 `viewer_controls.js` 负责打开、关闭、焦点回收、Escape、Tab 焦点循环和视口切换。

手机端关闭时侧栏使用 `inert` 与 `aria-hidden` 避免键盘或辅助技术进入屏外内容；打开时触发按钮更新 `aria-expanded`，焦点移动到关闭按钮。桌面端取消这些限制，保留原来的常驻侧栏。筛选按钮上的数字只统计已勾选条件，不把搜索词算作筛选项。

## 网址状态

网址参数使用可读、可重复的单数键：`q`、`tag`、`cat`、`vocal`、`version`、`staff`、`type`、`channel`、`sort`、`dir`。多选使用重复参数，例如 `?tag=idol&tag=vocaloid`，不依赖自定义分隔符，因此包含空格或标点的频道名称也能安全编码。

每次已完成的搜索、勾选、清空或排序都会写入一条历史记录；浏览器前进/后退时，页面重新读取状态并刷新结果。默认搜索为空、默认排序不写入网址。页面只恢复当前数据中真实存在的筛选值，并忽略未知排序字段或过期参数；其他非本功能参数保持原样。

## 测试边界

静态测试验证两页都加载共享资源、包含抽屉语义结构，并确保共享脚本实现历史状态、无效值过滤和移动端可访问性。真实浏览器检查覆盖：搜索状态刷新恢复、排序参数、手机打开/关闭抽屉、选择筛选后的计数与结果、网址参数，以及返回上一历史状态。最后继续运行完整 Python 测试、JavaScript 语法检查、数据校验和站点构建。
