# 歌曲与视频查看页资源拆分设计

## 目标

`index.html` 和 `video_viewer.html` 分别还包含上千行内联样式与数百行内联脚本。虽然这两个页面已经在功能上稳定，但任何样式或搜索逻辑的修改都会产生巨大 HTML 差异，也不利于浏览器独立缓存静态资源。

本阶段将两页各自拆成页面骨架、样式和脚本，但不改数据流、筛选规则、分页、展开交互、文案或视觉。新结构为 `assets/index.css`、`assets/index.js`、`assets/video_viewer.css` 和 `assets/video_viewer.js`。

## 方案选择

1. **页面级机械拆分（采用）**：每页保留自己的 CSS 和 JS，原有代码块逐行搬移。优点是风险低、差异清晰、无需新增构建工具。
2. **立即提取公共样式和脚本**：两页确实共享一些导航、标签、回到顶部与格式化代码，但同名函数在筛选字段和排序默认值上存在差异。此时合并会把结构重构和行为重构捆绑在一起，不利于定位回归。
3. **引入打包器和 ES Modules**：长期可以做更细的依赖边界，但会增加本地启动、CI 和 GitHub Pages 构建复杂度，对当前静态应用没有必要。

因此先完成可验证的页面级拆分。待两页的外部资源边界稳定后，再通过独立任务提取有实际收益的纯函数或设计令牌。

## 发布与验证

`build_site.py` 的显式白名单增加四个资源，任一文件缺失都会在发布前失败。静态测试锁定每页唯一的样式/脚本引用、禁止可执行内联脚本，并检查搜索、筛选、展开和文件协议提示等关键函数仍在对应资源中。

真实浏览器验收覆盖：主页数据数量、别称搜索、组合筛选和详情展开；视频页数量、视频搜索、展开与链接；两页的手机宽度溢出；所有本地资源状态和页面脚本错误。
