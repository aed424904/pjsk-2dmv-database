# 歌曲投稿时间、细粒度筛选与全量导出设计

## 目标与口径

首页歌曲表新增“视频网站投稿时间”列，与“实装时间”并列并可独立排序。该列统一读取歌曲的 `releasedAt`：构建流程优先采用已关联本家 MV 的最早上传时间；没有可用本家视频时沿用主数据中的原曲发布时间。因此翻唱曲展示的是原曲投稿时间，而不是 Project Sekai 官方翻唱视频上传时间。歌曲类型以主数据的 `isNewlyWrittenMusic` 为唯一来源，`true` 映射为“原创曲”，其余映射为“翻唱曲”，并写入合并数据，供网页和导出共用。

筛选栏增加“歌曲类型”和“角色”两组。角色来自所有歌声版本的 `characters`，使用 `characterType:characterId` 作为稳定筛选键，并通过现有角色主数据转换为显示名；同一歌曲内重复出现的角色只计数一次。多个角色继续沿用现有筛选体验，满足任一选中角色即可。团队筛选通常仍是同组 OR，但 V.S. 是精确条件：选中 V.S. 后，仅保留团队标签集合严格等于 Virtual Singer 的歌曲；若同时选中互斥团队，结果自然为空。所有新增条件写入 URL，支持刷新、前进和后退恢复。

## 导出与验证

Excel 使用一个工作簿、四张明细表：歌曲总览、歌声版本、视频、Staff。歌曲总览覆盖完整曲库；其余表按一对多关系展开，避免在一个单元格里丢失角色、视频或贡献者信息。日期写为真正的 Excel 日期值，表头启用筛选，首行冻结，列宽按内容类型限制，保证可排序和后续维护。

验证包括三层：Python 单元测试确认曲目类型与原曲投稿时间解析；静态资源测试确认筛选组和排序字段接入；Playwright 浏览器检查确认日期排序、V.S. 精确筛选、角色筛选、歌曲类型筛选及 URL 状态。工作簿最终检查关键范围、公式错误扫描，并分别渲染四张表进行目视校验。
