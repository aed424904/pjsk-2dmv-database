# 数据采集可靠性修复设计

## 范围

本次保持现有 JSON 格式、目录结构、一键更新入口和前端消费方式不变，只修复采集与发布链路中的高风险可靠性问题。

## 设计

1. YouTube API Key 只允许通过 `YOUTUBE_API_KEY` 环境变量提供。未配置时自动使用 yt-dlp，不在源码中保存任何默认密钥。
2. YouTube Data API 请求统一使用连接/读取超时。对 429 和 5xx 响应进行有限次数的指数退避重试，并尊重服务端的 `Retry-After`。
3. 每个视频来源选择文件名时间戳最新且 JSON 有效的非空快照。视频数量只作为数据质量指标，不再决定快照优先级，因此来源中的合法删除能够进入数据库。
4. 新旧快照比较覆盖所有影响数据库的采集字段，包括描述、频道、缩略图和统计量，避免描述更新后 staff/歌手抽取结果不刷新。
5. 数据库校验使用项目相对路径，错误时返回非零退出码。自动更新在构建结束后强制执行校验，校验失败则整次更新失败。

## 错误处理

API 请求在达到最大重试次数后返回失败，并允许现有 API→yt-dlp 回退逻辑接管。抓取失败或返回空列表时继续沿用最后一个有效快照。损坏、空数组或标记为非完整状态的快照不会被构建过程选中。

## 验证

使用 `unittest` 和 mock 响应离线验证：环境变量密钥读取、可重试状态码、最新快照选择、损坏/空快照过滤、内容字段变化检测，以及校验器退出状态。最后执行项目完整 unittest 测试发现和 Python 语法编译检查。
