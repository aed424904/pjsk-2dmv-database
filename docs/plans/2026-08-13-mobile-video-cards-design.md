# 手机端视频卡片与浏览器冒烟验收设计

## 问题与目标

`video_viewer.html` 在 390px 宽度下已经没有横向溢出，但当前做法是把七列表格压缩成五列，并直接隐藏版本、频道、播放量和日期。结果是视频标题只剩极少字符，用户必须反复展开才能区分条目。

本阶段只改手机端的信息组织：桌面端继续使用高密度表格；窄屏把每条视频重排为“类型眉题 + 两行标题/曲名 + 元信息胶囊 + 展开指示”的紧凑卡片。所有字段仍由原有数据渲染，整卡的点击、Enter/Space 键展开、搜索和筛选行为不变。

## 视觉方向与方案比较

视觉延续现有资料库操作台的浅色工业/编辑风格：冷灰背景、纸面白卡、蓝色精确强调，不引入新字体、大面积渐变或与桌面端脱节的装饰。记忆点是“像唱片档案卡的移动视频目录”：信息密度高，但标题始终有足够的阅读空间。

1. **响应式卡片（采用）**：为四个元数据字段增加一个包装层和 `data-label`，桌面端使用 `display: contents` 保留原网格，手机端则把包装层变为可换行元信息区。字段完整、无水平滚动，且桌面布局不变。
2. **保持压缩表格**：代码最少，但标题与曲名不可辨识，并持续丢失元数据。
3. **使表格水平滚动**：可保留所有列，但主要标题和展开按钮会移出屏幕，单手浏览成本高。

## 结构与可访问性

视频行新增 `.video-meta` 包装层，其中保留版本、频道、播放量和日期四个原有 span。每个 span 通过 `data-label` 提供手机端的字段名，CSS `content: attr(data-label)` 只负责视觉呈现；实际值仍是 DOM 文本，辅助技术不会失去内容。

卡片继续使用原有 `role="button"`、`tabindex="0"`、`aria-expanded` 和详细标签。手机端隐藏只对应桌面列的表头，不隐藏任何数据字段。展开后详情面板与卡片形成上下连续的组合，不会在视觉上被误认为下一条记录。

## 可重复浏览器验收

新增 `scripts/browser_smoke_check.mjs`，使用 Node 内置 HTTP 服务器从 `dist/` 提供站点，并直接通过 Playwright 库启动 Chrome。脚本自行调用站点构建，使用系统分配的临时端口，在 `finally` 中关闭浏览器和服务器，不留后台进程。

冒烟检查固定验证：主页别称搜索与详情展开；视频搜索与键盘展开；编辑器标签切换；旧入口跳转；390px 下的卡片网格、元数据可见性和横向溢出；本地资源错误和页面异常。脚本输出 JSON 摘要并用进程退出码表示成败。

`package.json` 只提供 `check:browser` 命令和精确的 Playwright 开发依赖，不引入 Playwright Test 框架，也不改现有 Python 测试与发布流程。
